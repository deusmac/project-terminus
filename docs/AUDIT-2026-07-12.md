# Terminus Full Audit - 2026-07-12

Scope: complete read of index.html (all 1339 lines), Start Terminus.bat, .claude config,
CLAUDE.md, THINKING.md. Every finding cites the line in index.html unless noted.
Ranked by severity: what bites a real bid first.

## SEVERITY 1 - Trust and correctness (fix first)

### 1. The footer and Sources modal claim the engine uses EFFECTIVE Ixe. It uses GROSS Ix.
- Where: index.html line 485 (footer: "effective section properties (Ixe ...)" and the
  formula "L = (384 E Ixe / 5wn)^1/3"), and line 1323 (renderSources: "section properties
  (Ixe, Ma) were transcribed").
- Why it matters: the entire value proposition is that JC can defend these numbers. An
  engineer who reads the footer, then checks the SSMA section-property table's Ixe column,
  will find the app's stored values do NOT match Ixe (they are gross Ix, on purpose, per the
  CLAUDE.md landmine) and will conclude the app is wrong. The one place that gets it right
  is the doc-panel meta line 1095 ("Ix ... gross, deflection").
- Exact fix: in the footer replace "SSMA-published effective section properties (I<sub>xe</sub>,
  M<sub>a</sub>, ...)" with "SSMA-published section properties (gross I<sub>x</sub> for
  deflection, matching SSMA's own limiting-height tables; M<sub>a</sub> for strength; ...)"
  and change both I<sub>xe</sub> occurrences in the formula text to I<sub>x</sub>. In
  renderSources change "(I<sub>xe</sub>, M<sub>a</sub>)" to "(gross I<sub>x</sub>,
  M<sub>a</sub>)". Re-run Validate after (must be unchanged; this is copy only).

### 2. The composite toggle multiplies STRENGTH by 1.08 with no published basis.
- Where: line 687: `ld*=DB.compositeFactor; ls*=DB.compositeFactor;`
- Why it matters: composite action (gyp both sides) is a stiffness phenomenon. Applying the
  +8 percent bonus to the strength limit `ls` is unconservative: for any strength-governed
  S125 case the app reports a taller allowable height than any table supports. 362S125-18
  at 5 psf is already strength-governed per the code's own comment (line 666), so this is a
  live path, not a theoretical one.
- Exact fix (minimal, safe): apply the factor to deflection only, i.e. keep
  `ld*=DB.compositeFactor;` and delete `ls*=DB.compositeFactor;`. The permanent fix is
  PRODUCT.md phase 1 item 1: replace the whole approximation with the actual SSMA composite
  tables (limiting heights PDF pp.19-20), already the CLAUDE.md backlog's top item.
- Guardrail: this changes displayed heights for composite-on interior cases. Run Validate
  (should be unchanged, it is exterior only) AND spot-check 600S125-18 composite cells
  against p.20 before and after; the COMPOSITE_ONLY table lookups bypass the factor and must
  stay identical.

### 3. The validation harness covers only exterior structural tables. Interior data is unvalidated.
- Where: SSMA_ANCHORS (lines 720-739); all 32 anchors are Curtain Wall (exterior) cells.
- Why it matters: SSMA_NONSTRUCTURAL (the S125 ladder JC uses daily for partitions) and the
  COMPOSITE_ONLY table have zero self-test coverage. A transcription typo there ships
  silently while the Validate button still shows green. The one interior spot value in the
  code comment (362S125-18 = 12'-2") is not in the harness.
- Exact fix: add 8-12 anchors transcribed from the Interior Wall tables (pp.19-20 composite,
  plus non-composite interior columns) covering 362S125-18, 362S125-30, 600S125-43
  non-composite, 600S125-18 composite at all three spacings, and one 800 row. Extend
  runValidation to route interior anchors through nonstructuralMembers with the right
  wallType and composite flags. Same exact-match standard as the structural set.

### 4. The AI parser's height regex grabs the FIRST feet-like number in the note.
- Where: line 1168: `t.match(/(\d{1,2})\s*(?:'|ft|feet).../)` with no context anchoring.
- Why it matters: real structural notes contain multiple feet values. A note like "ceiling
  at 9'-0", frame to deck at 24'-0"" sets the target to 9 ft, and the matrix will bless a
  stud that fails at the real 24 ft height. This is the most dangerous silent-wrong-answer
  path in the app: the user pasted a correct note and got a confident wrong result.
- Exact fix: use matchAll, filter candidates to the 8-40 ft window, take the MAXIMUM (walls
  frame to the tallest number in a framing note), and always echo the interpretation in the
  findings, for example: "Height read as 24'-0" (tallest of 9'-0", 24'-0" in the note),
  correct me if wrong." Echoing what was parsed is the real safety net.

## SEVERITY 2 - Misleading output (fix soon)

### 5. The BID PICK banner does not flag when the winner is an EQ estimate.
- Where: renderMatrix target banner (lines 954-964). globalBestPick sorts by mil, so a
  15-mil EQ estimate can beat every verified SSMA row and take "OPTIMAL BID PICK" with no
  EST marker in the banner (the EST chip only appears down in the table rows).
- Exact fix: in the banner template, when `best.member.est` is true append the amber EST
  chip and "estimate - verify in catalog" next to the pick. One line.

### 6. Parser maps "20ga" to 33 mil (structural) even in interior drywall context.
- Where: line 1147: `{25:18,22:27,20:33,...}`. Interior "20ga" conventionally means the
  30-mil drywall stud. The downstream filter partially compensates (line 1217 accepts both
  30 and 33), but the SPEC CHECKS OUT / OVER-ENGINEERED verdict can be computed against the
  wrong member.
- Exact fix: when parsed wallType is interior (or flange is 125), map 20ga to 30; keep 33
  for exterior or structural context. Echo the interpretation in the findings line.

### 7. ftInput clamps while typing.
- Where: lines 858-861. Typing the "1" of "14" instantly clamps to 8 ft and re-renders the
  matrix. Same class of bug as the wind-speed input JC already flagged; that one was fixed
  (lines 869-880), this sibling was not.
- Exact fix: copy the windV pattern: on input only apply values already in range, clamp and
  normalize on blur.

### 8. Start Terminus.bat lies when Python is missing.
- Where: the .bat suppresses stderr and prints "Server may already be running" on any
  failure, including Python not installed. A coworker without Python sees a dead page and a
  reassuring message.
- Exact fix: before starting the server add
  `where python >nul 2>&1 || (echo Python not found - just double-click index.html instead. & pause & exit /b)`.

## SEVERITY 3 - Latent fragility (fix opportunistically)

- renderDoc assumes the selected row still exists: line 1033 `block.rows.find(...)` is not
  null-checked. Safe today only because renderMatrix's alive-check always runs first in
  renderAll. Add `if(!row){state.selected=null; return renderDoc();}`.
- COMPOSITE_ONLY lookup keys by exact psf string (line 676). Any future load-preset change
  or wind-applied decimal silently returns N/R. Fine today; normalize with Number() and
  comment the constraint.
- fmtFtIn assumes integer inches (line 699); would print "12'-3.5"" if future data carries
  halves. Guard with Math.round inside fmtFtIn.
- Modals do not close on Escape and segmented buttons carry no aria-pressed. One keydown
  listener and one attribute in syncSeg; cheap wins.
- External EQ catalog URLs (lines 557-581) rot frequently (manufacturer PDF paths change).
  Save local copies into sources/ like the SSMA PDFs, same pattern, same audit-trail value.
- DB.version stamp says "2026-06" (line 591); bump whenever data changes.

## Not bugs, verified clean

- Engine math: deflection L = cbrt(384 E Ix / (5 w n)) and strength L = sqrt(8 Ma / w) are
  the correct closed forms; 0.7W applies to deflection only and exempts 5 psf; strength
  always uses full w. Independently re-derived during this audit against the 32 anchors.
- No XSS surface: the AI textarea is parsed with regex and never injected as HTML; external
  links carry rel="noopener"; no secrets, no network calls except Google Fonts.
- Composite toggle correctly hidden and inert for non-125 flanges (lines 687, 917).
- The 18-mil trap is properly guarded: company codes attach only to EQ rows (line 659) and
  plain SSMA 18-mil rows carry an explicit warning tag (line 975).
- Wind-speed input no longer fights the user; wind-calculator constants are reasonable for
  the labeled approximation.

## Structural and product-level gaps (these drive PRODUCT.md)

- No git repo. A single 90 KB file with no history; one bad edit is unrecoverable. git init
  is a 2-minute task and is doctrine (THINKING.md section 4 rule 1).
- Interior composite ladder still uses the +8 percent approximation instead of the published
  pp.19-20 tables (top backlog item; also permanently resolves finding 2).
- EQ heights are estimates calibrated to one anchor. The catalogs are public PDFs; giving
  them the same transcription treatment as SSMA upgrades EQ rows from EST to verified.
- No print or export. A bid pick dies in the browser; JC re-types it into the estimate and
  Jack reads outputs on a phone. A print stylesheet plus a copy-pick-summary button is the
  highest-leverage new feature per hour of work.
- No state persistence: a reload loses the whole criteria setup mid-takeoff (only the theme
  persists). localStorage save and restore of `state` is about 10 lines.
- Layout below roughly 700 px wide is unusable; matters only if phone use is expected.
